# Tikitaka 제품 스펙

버전 0.3 · 2026-10-01

## 최우선 제품 원칙: 심플함

**앱을 열고 버튼 하나로 바로 대화를 시작한다.** 3인 대화와 심플함이 핵심이며, 둘 사이에서 판단이 필요하면 심플함을 먼저 지킨다. 기능을 추가하거나 구조를 다시 설계해도 이 원칙은 유지한다.

첫 화면에는 “대화 시작” 버튼 하나만 둔다. 시작 전에 주제, 언어, Persona, 모델, 난이도를 고르게 하지 않는다. 고정된 두 AI 친구와 주제를 자동으로 준비하고, AI가 먼저 이야기한다. 마이크는 대화 동안 켜두며 사용자는 발화마다 버튼을 누르지 않는다. 첫 사용의 OS 마이크 권한은 필요한 시스템 절차로 처리한다.

대화 중 같은 버튼은 “대화 끝내기”로 바뀐다. 현재 화자와 짧은 자막, 상태만 보여준다. 설정·진단·기록 목록으로 기본 화면을 채우지 않는다. 내부 언어 선택과 테스트 도구는 별도 개발 화면 `/lab`에서만 제공한다. 한국어 검증과 영어 출시 전환은 서버/빌드 설정이며 사용자 시작 절차에 포함하지 않는다.

출시 Android 앱은 기본 마이크와 연결된 이어폰·Bluetooth의 입력 경로를 자동으로 사용한다. 시작 전에 마이크 목록을 고르는 절차를 두지 않는다. PC의 `/mic` 마이크 선택은 내부 검증 도구이며, 선택한 장치를 같은 브라우저에 저장해 다음 대화에 재사용한다. 휴대폰의 권한·오디오 경로 전환·연결 해제는 앱 내부에서 처리하고 실기기로 검증한다.

## 확정사항

1. 한국인을 위한 영어회화 앱이며, 최종 출시 MVP 언어는 영어다.
2. 한국어 음성 대화는 내부 개발과 UX 검증 단계다.
3. 음성은 첫 개발부터 포함한다. 텍스트 전용 제품을 먼저 출시하지 않는다.
4. 사용자가 마이크를 켜두고 자연스럽게 말한다. AI 발화 중 끼어들기를 필수로 지원한다.
5. Android MVP 출시 후 iPhone을 개발한다.
6. Persona, Orchestrator, LLM, 음성 처리를 분리한다.

이 내용은 원문 v0.1의 텍스트 우선, 음성 후순위 로드맵과 이전 Word 초안보다 우선한다.

## 핵심 가설

사용자가 대화 주제를 계속 만들어내지 않아도 두 AI의 다른 의견을 듣다가 스스로 참여하고 싶어진다. AI는 교사가 아니라 서로 다른 성격의 친구로 행동한다. 대화 중 문법 평가로 흐름을 끊지 않는다.

## 단계

| 단계 | 언어와 플랫폼 | 완료 목표 |
|---|---|---|
| PC 내부 프로토타입 | 한국어 기본, 영어 전환 가능 | 생성 취소, 음성 재생 중단, 사용자 반영, 두 AI 교대 검증 |
| Android 내부 검증 | 한국어 음성 | 실제 스피커·마이크, 음성 종료 감지, 끼어들기, 지연 검증 |
| 출시 MVP | 영어 음성 Android | 초중급 표현, 서로 구분되는 AI 음성, 안정적인 자연 참여 |
| 이후 | iPhone 및 확장 | 제품 반응을 바탕으로 iOS와 학습·기억 기능 확장 |

## 대표 시나리오

### 관찰

“대화 시작”을 한 번 누르면 주제를 자동으로 정하고 민지 A가 의견을 말하고 준호 B가 반응한다. 사용자에게 답을 강요하지 않는다. A와 B의 음성을 겹치게 재생하지 않는다. 다음 발화는 이전 음성의 실제 종료를 기준으로 예약한다.

### 참여

A가 말하는 동안 사용자가 “아니, 나는 반대인데”라고 말한다. 클라이언트는 음성 시작 감지 시 A 음성을 즉시 중단하고 서버에 사용자 발화 시작을 알린다. 서버는 생성과 예약을 무효화한다. 사용자 말이 확정되면 지목된 AI, 지목이 없으면 A가 먼저 반응하고 다른 AI가 이어받는다.

### 다시 관찰

사용자가 말한 뒤 조용히 있으면 A와 B가 의견을 이어간다. 대답을 기다리는 상태에 영구히 머무르지 않는다. 짧은 머뭇거림은 새 AI 턴 시작을 보류한다.

### 정지와 종료

일시정지는 AI 생성, 재생, 마이크 캡처를 함께 멈춘다. 재개는 명시적 조작으로만 한다. 종료나 연결 끊김 후 AI가 계속 생성되지 않는다.

## Phase 1 필수 기능

- 고정된 Facilitator A와 Challenger B 한 쌍. Persona는 데이터로 정의.
- 가볍게 의견이 갈리는 주제 5개 자동 선택. 한국어·영어는 개발 설정.
- AI 음성 교대, 상시 마이크 입력, 발화 시작·종료 신호, 재생 중 끼어들기.
- 생성 중 사용자가 끼어들면 오래된 AI 결과와 재생 큐 폐기.
- 완성된 사용자 전사와 메시지 기록. 중단된 AI 발화는 별도 표시.
- 단일 버튼 시작·종료. 비활성·연결 오류 시 자동 정지와 명시적 재시작. 개발 화면에서만 추가 세션 제어 제공.
- 서버가 반환한 순서대로 메시지 표시, 입력 재전송 중복 방지.
- 유한한 세션 시간·호출 횟수, 익명 로컬 세션, 진단 이벤트.

PC 테스트 화면의 텍스트 입력은 마이크나 STT 없이 엔진을 검증하는 보조 기능이다. 출시 음성 UX를 대체하지 않는다.

## 초기 제어값

아래 값은 검증을 통해 바꿀 개발 기본값이다.

- AI는 1~2문장, 한국어 180자·영어 400자 상한을 목표로 한다.
- 음성 재생 완료 후 1.5초 뒤 다음 AI 턴을 준비한다.
- PC 발화 종료 감지는 마지막 음성 활동·전사 변경 이후 1.2초를 기본으로 한다. STT 최종 결과 없이 중간 전사만으로 확정하지 않는다.
- 소음이 발화 시작으로 감지됐지만 전사가 없으면 클라이언트가 발화 취소를 알려 복구한다. 마지막 발화 활동 신호 이후 6초간 확정 전사가 오지 않으면 안전하게 정지한다. 종료 감지 설정과 이 타임아웃은 다른 값이다.
- AI 음성 재생 종료 신호가 유실되면 최대 30초 후 정지한다. 사용자가 없는 상태에서 다음 턴을 자동 진행하지 않는다.
- 세션 최대 10분, LLM 호출 최대 60회. 실패와 취소도 호출 수에 포함한다.
- 마이크 시작에는 사용자의 시작 조작과 브라우저/OS 권한이 필요하다.

## 수용 기준

| 시나리오 | 통과 조건 |
|---|---|
| 즉시 시작 | 최초 OS 권한을 제외하고 시작 버튼 1회로 음성 대화가 열린다. 사전 선택·설정·추가 확인 화면이 없다. |
| 화면 단순성 | 기본 화면에 선택기·텍스트 입력·진단·통계가 없으며 개발 화면과 분리된다. |
| 관찰 | 사용자 입력 없이 A와 B가 차례로 말하고 음성이 겹치지 않는다. |
| 생성 중 끼어들기 | 이전 요청 결과가 늦게 돌아와도 메시지나 음성으로 게시되지 않는다. |
| 재생 중 끼어들기 | 재생을 멈추고 중단 상태를 기록한다. 해당 발화의 재생 완료 신호로 새 AI 턴이 열리지 않는다. |
| 사용자 연속 발화 | 모든 확정 입력을 순서대로 보존하고 최신 입력에 대한 응답만 게시한다. |
| 잘못된 완료 신호 | 다른 메시지·이전 revision·다른 연결의 완료 신호는 무시한다. |
| 정지·종료 | 예약, 생성, 음성이 멈추고 마이크 자원을 반환한다. |
| 재접속 | 기록을 복원하고 정지 상태를 유지한다. 사용자가 재개해야 한다. |
| 오류 | API 키, Provider 응답 원문 등 내부 정보를 UI와 로그에 노출하지 않는다. |

## 제외 범위

SNS, 친구 Persona 공유, 장기 기억, MBTI 선택 UI, 결제, 게임화, 정교한 발음 점수, 학습 성과 평가, 다중 모델 최적화는 이후 단계다. **음성과 끼어들기는 제외하지 않는다.**

## 검증 지표

첫 자발적 참여까지의 시간, 직접 초대 없이 참여한 세션 비율, 재미·부담 피드백, 음성 시작부터 재생 중단까지의 시간, 사용자 발화 종료부터 응답 재생까지의 시간, 오탐 끼어들기 횟수를 관찰한다. 대본 기반 데모는 제어 흐름을 검증하며 실제 LLM 대화의 재미나 영어 학습 효과를 입증하지 않는다.
