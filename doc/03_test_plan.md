# 개발 중 테스트 계획

## PC 자동 테스트

- 사용자 입력 없이 A와 B의 교대.
- 실제 재생 완료 전 다음 AI 요청 금지.
- 생성 중 끼어들기와 취소를 무시하는 늦은 응답 폐기.
- 재생 중 끼어들기와 오래된 완료 콜백 무시.
- 연속 사용자 입력, 동일 요청 재전송, 정지 중 입력, 종료 후 입력 거절.
- 연결 끊김·교체·heartbeat 만료 정지, 서버 복원 시 정지.
- Gateway 오류 및 타임아웃, 호출 상한, 불필요한 자동 재시도 금지.
- WebSocket 인증, 메시지 크기 제한, 알 수 없는 명령 처리.
- 음성 클라이언트의 발화 모으기, 최종 전사 전송, 취소 토큰, 오류 복구.

실제 유료 API와 마이크 없이 FakeGateway와 클라이언트 이벤트로 실행한다.

## PC 브라우저 수동 테스트

1. 로컬 서버를 실행하고 Chrome에서 localhost 화면을 연다.
2. 시작 화면에 설정 선택 없이 버튼 하나가 있는지, 개발용 데모 표시가 있는지 확인한다.
3. “대화 시작”을 한 번 누르고 최초 마이크 권한을 허용한다. 추가 주제·언어 선택 없이 시작되는지 확인한다.
4. A와 B가 겹치지 않고 말하는지 확인한다.
5. A가 말하는 중 의견을 말해 음성이 멈추는지 확인한다.
6. 중간 전사는 표시되고 말이 끝난 후 사용자 메시지 1개로 확정되는지 확인한다.
7. 짧게 머뭇거려도 내 말이 여러 메시지로 쪼개지는지 관찰한다.
8. 정지 시 마이크 사용 표시가 사라지고 새 AI가 말하지 않는지 확인한다.
9. 새로고침 후 기록은 돌아오고 자동 재생은 되지 않는지 확인한다.
10. `/lab`에서 영어 설정과 텍스트 진단 모드도 확인한다.

브라우저 내장 인식은 지원 브라우저와 인식 서비스에 따라 실패할 수 있다. 자동 UI 검사만으로 실제 마이크/STT/스피커의 성공을 보고하지 않는다.

## Android 실기기 검증

- 기기 스피커 음성을 사용자 음성으로 오인하는지, 이어폰과 Bluetooth에서 어떤지.
- 소음, 작은 목소리, 긴 머뭇거림, 여러 번 끼어들기.
- 사용자 음성 시작→AI 음성 중단, 사용자 말 종료→응답 재생 지연.
- 마이크 권한 거절과 철회, 앱 비활성·화면 잠금·전화 수신 시 자원 반환.
- 실제 네트워크 지연과 끊김, Android 오디오 포커스와 라우팅.

PC 프로토타입 이후 Android SDK와 실제 기기를 준비해 실행한다. PC 브라우저 검증 결과를 실기기 검증으로 대체하지 않는다.
