# Android MVP 구현 현황

2026-10-09. 사용자는 영어 Android MVP 완성을 요청했고 자리를 비운 동안 개발·검사·커밋·푸시를 허용했다. 실물 마이크는 사용하지 않고 합성 음성으로 시험한다.

## 현재 확인된 결과

- 8103 실제 API 서버에서 합성 TTS→STT 통과.
- Codex 내장 브라우저에서 한국어·영어 각각 실제 AudioWorklet 입력 → OpenAI 전사 → GPT 응답 → OpenAI TTS 재생 통과. 첫 민지 발화 중단 후 준호·민지 재생 완료. 두 결과 모두 provider=openai, speakers=a,b,a, played=b,a, interruptions=1. 중단된 음성은 재개되지 않았다.
- 영어 합성 입력은 “Junho, I prefer winter. Summer is too hot.”으로 정확히 전사되었다.
- Python 56개, JavaScript 45개, Android JVM 12개, 총 113개 검사 통과. Android 검사는 음성 분절, HTTP/WebSocket 제어, 취소·늦은 응답, 권한·단일 버튼 화면을 포함한다. 물리 마이크, 스피커 에코와 Android 기기는 아직 검증하지 않았다.
- GitHub Actions의 사전 설치 SDK에서 Android 테스트·lint·APK 빌드·서명 검사가 [52e317f 빌드](https://github.com/jjome/tikitaka/actions/runs/37841250993)로 통과했다. 로컬 SDK 설치는 하지 않았다. lint 오류는 0개이며 사용 가능한 Gradle 새 버전 안내 경고 1개가 남는다.
- 최초 APK 컴파일·테스트는 통과했으나 lint에서 개발용 네트워크 설정의 속성 누락을 발견해 수정했다. 권한 승인 시점에 따른 시작 누락도 회귀 검사로 막았다.
- 세션 7일 보관, 소유 토큰으로 즉시 삭제, 삭제 시 처리 중 음성 요청 취소, 사용하지 않는 대화 컨트롤러의 메모리 해제를 구현했다.

## 설치 파일

- 소스: `52e317f` · 앱 버전 `0.1.0-dev` · Android 8 이상.
- 파일: `.runtime/artifacts/52e317f/app-debug.apk` (1,371,448 bytes).
- SHA-256: `ca058f251ca028feecf5c36db451c1f55be790725bc883cfe76add0833e83ace`.
- 서명 검사는 CI에서 통과했고 로컬 다운로드 후 체크섬을 대조했다. 검사 보고서는 같은 폴더의 `reports/`에 저장했다.
- PC 한국어 개발 화면: `http://127.0.0.1:8103/`. Android 앱은 빌드 기본값인 영어를 명시해서 세션을 생성한다.

## 음성 응답 시간

영어 합성 파일 입력 종료부터 응답 재생 시작까지 한 번씩 측정했다. 최초 8,380ms, 짧은 응답 안내 적용 후 6,100ms, PCM→WAV 출력 적용 후 6,821ms였다. 마지막 실행은 전사 1,479ms, 전체 3개 응답 시험 43,074ms이며 모든 끼어들기·재생 조건을 통과했다. 표본이 작고 생성 내용·네트워크도 달라 성능 개선율로 해석하지 않는다. PCM 출력은 압축·디코딩 단계와 불확정 헤더를 제거하지만 전송량이 늘고, 이 측정에서는 추가 지연 개선을 입증하지 못했다.

현재 대화는 전사→GPT→음성 생성 전체 수신→재생 구조다. **ChatGPT 음성과 같은 낮은 지연을 달성했다고 볼 수 없다.** 더 짧은 응답 지연에는 스트리밍 음성 출력 또는 Realtime 전송과 별도 취소·에코 검증이 필요하다.

## 휴대폰에서 이어서 확인할 순서

1. SDK 약관에 동의한 뒤 공식 platform-tools를 준비하고 Android 기기를 USB로 연결한다. 기기에서 USB 디버깅 신뢰 확인을 처리한다.
2. PC의 실제 API 서버 8103을 유지하고 `scripts/install-android.ps1`을 실행한다. 최신 로컬 APK를 설치하고 PC 서버 연결 및 앱 열기를 수행한다.
3. 앱의 시작 버튼을 누르고 처음 마이크 권한을 허용한다. 영어로 말하고 민지·준호 답변, 끼어들기, 화면 잠금·전화·이어폰 연결 해제를 확인한다.

현재 APK는 PC 서버에 연결하는 내부 테스트용이며, 단독으로 외부 네트워크에서 동작하는 스토어 출시본이 아니다. 실제 휴대폰이 연결되지 않아 설치·입력·스피커 검증은 수행하지 않았다.

## 이번 구현 순서

1. 실제 API 검증 결과 보존, PC 기본 화면과 영어 경로 안정화.
2. Android 네이티브 클라이언트: 단일 버튼, 기본 영어, 고정 두 친구, AudioRecord 입력, 로컬 끼어들기, API 전사·음성 재생, 앱 중단·오디오 포커스 손실 시 자원 반환.
3. Android 제어·음성 분절의 자동 검사와 빌드 검증. API 키는 앱에 넣지 않는다. 개발은 USB 포트 역방향 전달로 로컬 서버와 연결한다.
4. 서버 배포 준비와 보관·삭제 정책, 실행/검사 안내, 남은 출시 조건 정리.

## 출시 완료 조건

실기기에서 권한·유선/Bluetooth 경로·스피커 에코·끼어들기·백그라운드 전환을 확인하고, 운영 HTTPS 서버와 사용자 접근 제어·비용 상한, 서명 키, Google Play 계정 및 스토어 정보를 준비해야 한다. APK 컴파일과 스토어 출시를 구분한다. 준비되지 않은 계정이나 배포 주소를 임의로 만들지 않는다.

## Android 선택

Java 17 + Android Gradle Plugin 8.13.2, 최소 Android 8(API 26), compile/target API 36. 네이티브 AudioRecord/MediaPlayer와 OkHttp로 기존 세션 계약을 사용한다. WebView의 브라우저 음성 인식에 의존하지 않는다. release 서버 주소는 빌드 설정으로 HTTPS를 지정하며 debug는 localhost:8103 및 adb reverse를 사용한다. 한국어 검증은 빌드 언어 설정으로만 전환한다.
